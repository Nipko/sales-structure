# H2 — Production quality evidence

The previous scorer read the first 40 text messages, treated a text-only judge's `resolved` opinion as operational verification, and inserted another row each time a resolved conversation was queued again. It had no privacy fence or comparison against a transcript changed while the provider was working.

## Implemented contract

- `conversations.qa_revision` advances on public message insert/update/delete and relevant conversation changes (state, attribution, contact and metadata). Internal notes never enter the public transcript, coverage counts or source revision. The message trigger updates the triggering tenant's schema explicitly. Quality bookkeeping and independent verification updates do not recursively advance the revision.
- Production scoring holds the shared `agent-privacy:<schema>` transaction lock through transcript capture, provider work and finalization. A per-conversation advisory lock plus the unique `(conversation_id, source_revision, rubric_hash)` index deduplicates concurrent and repeated jobs. A final conversation row lock compares the captured revision; concurrent source edits raise `quality_source_changed` and the job retries without saving stale evidence.
- The bounded input keeps the latest 60 text messages, up to 24,000 UTF-16 units, including the closing turn. Coverage records total/text/selected/omitted messages and truncation, including omitted media and Unicode truncation. A partial transcript cannot produce a definitive conversational-resolution boolean.
- Each score stores its selected message IDs, transcript hash, source revision, rubric hash and configuration provenance. Configuration JSON is captured privately only when the current persona version exactly matches the conversation's recorded version. Missing historical configuration is explicitly `unavailable`; current configuration is never substituted for an older one.
- `conversational_resolved` and its reason are opinions. `operational_outcome` is `unknown`; the scorer never writes the conversation's independent `resolution_verified` field. Legacy v1 verification flags are excluded from new QA and AgentQuality readers. Managed guarantees require an explicit operational source and a complete verified denominator; unknown evidence cannot become a zero rate or a breached guarantee.
- Summary, drill-down and AgentQuality readers select the current source revision and exact current rubric hash through SQL parameters, filter erased contacts, and expose partial coverage and unknown outcomes. A rubric edit invalidates old evidence even without a version-string bump. AgentQuality cannot call production evidenced solely from high text scores. Durable attention snapshots carry evidence policy v2; old cached/persisted certifications do not survive rollout as current evidence.
- Erasure obtains privacy, identity-table and ordered memory locks before resolving/deleting the unified contact family. Under that fence it deletes quality scores (including private snapshots and derived prose), cancels/clears sampling item references, and calls the widget session erasure helper. A job after erasure exits before sending any transcript to the provider.
- Job return values distinguish `scored`, `already_scored`, `insufficient_messages`, `erased` and `unavailable`. Provider/parse errors and concurrent source changes fail the job for retry. Daily sampling remains a separate denominator and queue-acceptance report; an unanswered conversation remains eligible even when its transcript cannot be scored.
- The dashboard explains opinion versus verified outcomes in Spanish, English, Portuguese and French. It shows unavailable reads as errors with retry, and unknown verification as unknown. QA cards no longer invent a `0%` comparison with a prior period that was never queried.

## Evidence and limits

Fourteen PostgreSQL QA tests exercise real revision triggers, concurrent job deduplication, message/state edits while the judge waits, privacy lock ordering and erasure in both directions, late retries, missing historical config, tail selection, internal-note exclusion, old rubric rejection, and invalidation after a later message. Two cases use a real PrismaClient and the production tenant query wrappers to bootstrap both the runtime helper and the SQL-template block from the original base schema, then score and erase evidence. Required attribution/resolution columns exist before either path creates its triggers; later historical ALTER statements are no longer a dependency. These cases also verify UUID-array, JSON, advisory-lock and regclass serialization. Unit tests cover character/media/Unicode loss, strict judge parsing, consumers, legacy attention migration, and unknown managed guarantees. Dashboard server rendering checks all four locales.

This is an integrity foundation, not an operational outcome oracle. Actual mission completion still needs canonical, task-specific evidence; none is fabricated from chat wording or a tool's apparent success. Scores with unavailable historical configuration remain conversational diagnostics and cannot replay an exact historical agent. Partial transcripts remain partial; no full-conversation claim is made. Provider model weights and nondeterminism are not certified by the rubric's requested model identifier. The shared privacy transaction occupies a database connection while the judge works (bounded to 120 seconds); a timeout aborts persistence and the job retries. Browser interaction was not exercised in this subtask; rendering and TypeScript checks provide the recorded UI evidence.
